# festival — 공식 정보 수집 절차 (매일)

> 예약 작업이 이 문서를 읽고 그대로 따른다. 작업 규칙(커밋 작성자, 한글 커밋, push 전 검증)은 [AGENTS.md](AGENTS.md)를 따른다.
> 저장소: `~/Documents/workspace/festival-log` (시작 전에 `git pull`)

## 수집 대상

- 페스티벌 코드마다 `src/data/catalog/series/<이름>.ts` 의 `sources` 에 있다. 한 항목은 `{ method, value, lastScrapedPostDate }` 이다.
  - `method: '인스타'`, `value: '@아이디'` → `https://www.instagram.com/<아이디>/`
  - `method: '공홈'`, `value: 'https://…'` → 공식 홈페이지 공지 게시판
- `lastScrapedPostDate` = 이 대상에서 마지막으로 확인한 게시글 날짜. **사용자가 아니라 이 절차가 갱신한다.**

## 절차

1. 저장된 수집 대상을 모두 확인한다.
2. 대상마다 `lastScrapedPostDate` 이후의 새 게시글이 있는지 본다.
   - 인스타는 로그인 없이 최근 12개만 보인다. 매일 새 글 확인에는 충분하다. **로그인 화면이 나와도 비밀번호를 입력하지 않는다.** 그 대상은 "확인 못함"으로 기록하고 다음으로 넘어간다.
   - 공홈은 목록에서 날짜를 보고, 새 글 본문을 페이지 안에서 키워드로 거른다. 일치한 글만 연다(토큰 절약).
   - 모든 대상에 새 글이 없다면 아무것도 바꾸지 않고 마무리의 보고로 간다(지도 남은 것은 그래도 알린다).
3. 새 글 중 **"<회차 연도>" 와 다음 키워드**가 함께 있는 글을 반영한다(한/영 둘 다 본다).
   - **TIMETABLE(타임테이블)** → 그해 연도 파일 `src/data/catalog/<이름><연도>.ts` 의 스테이지·공연. 한국어판과 영어판이 있으면 서로 맞춰 보고, 본문의 팀 수와 맞는지 확인한다. 무대 위 행사는 id 에 `-event-` 를 넣는다.
     - 그 회차의 `closedTabs`(`CATALOG` 항목)에 `'timetable'` 이 있으면 뺀다(타임테이블 탭을 연다). LINEUP 을 넣을 때도 같다.
     - 무대 색·아이콘은 연도 파일이 아니라 페스티벌 코드 파일(`src/data/catalog/series/<이름>.ts`)의 `theme.stages` 에 무대 키로 넣는다. 없는 무대 키가 있으면 테스트가 실패한다. 처음 보는 무대면 그해 포스터 색에서 색을 고르고 아이콘은 `STAGE_ICONS`(`src/data/schema.ts`) 중에서 고른 뒤, 사용자가 확인하도록 TODO 의 "디자인" 섹션에 남긴다.
   - 그해 TIMETABLE 이 아직 없으면 **LINEUP(최종 라인업) / "라인업"** 글을 찾아 `lineup` 에 1차, 2차, 3차 … 순서대로 **뒤에 덧붙인다**(앱은 가장 최근 포스터를 맨 위에 보여 준다). 포스터마다 alt 에 아티스트·날짜·장소를 적는다.
   - **MAP(지도·행사장 안내도·사이트맵)** → 지도 탭에서 쓰는 것이라 안내 이미지(`guides`)로는 넣지 않는다.
     - **같은 장소라도 무대·게이트·티켓부스 배치는 해마다 바뀔 수 있다.** 그해 공식 지도를 지금 앱 지도(그 페스티벌 코드의 지도)와 비교해서, 배치가 같으면 그 회차의 `closedTabs` 에서 `'map'` 을 빼서 지도 탭을 열고(새 내용이라 `updatedAt` 도 오늘로), TODO "다가오는 회차 지도"의 그 줄을 끝낸다.
     - 처음 나온 지도이거나 배치가 다르면 원본을 `map-src/<코드>/official-map-<연도>.<확장자>` 로 저장한다. 그리고 TODO "다가오는 회차 지도"의 그 회차 줄에 "공식 지도 나옴(글 날짜·주소), 원본 위치"를 적는다.
     - 지도를 그리는 일(레이어 지도, [MAP.md](MAP.md))은 사용자와 함께 하므로 이 절차에서는 하지 않는다. 대신 보고 맨 앞에 "지도 그릴 것"으로 알린다. 원본 저장만으로는 앱이 바뀌지 않으니 `updatedAt` 은 그대로 두고 지도 탭도 닫아 둔다(새로 그린 지도를 넣을 때 연다).
     - 공식 지도가 공식 앱이나 지도 서비스의 축제 지도(카카오맵·네이버 지도)에만 있으면 그 사실과 위치를 TODO 줄에 적는다. 지도 서비스 화면은 저장하지 않는다(그릴 때 눈으로 위치만 참고한다, [MAP.md](MAP.md)).
   - **CHECKLIST(유의사항·주의사항·안내)** → 이미지는 `src/assets/guides/guide-<연도코드>-<이름>-NN.webp`(webp 품질 80)로 넣고 `guides` 에 묶음으로 추가한다. 글로 된 안내는 요약해서 `notices` 에 더한다.
   - **TICKET(티켓 오픈·예매처)** → 예매처가 새로 나오거나 바뀌었으면 그해 연도 파일의 `…_TICKETS` 를 고친다(글이 거는 예매 페이지 주소로. 예매처별 주소 모양은 `src/data/catalog/tickets.ts` 의 `SELLERS`, 없는 예매처면 거기에 더한다). 정보 탭의 티켓 제목 옆 칩으로 나온다.
   - 위에 해당하는 글이 없으면 반영은 건너뛰고 5(확인 날짜 갱신)로 간다.
4. 주의사항과 안내 이미지는 **차곡차곡 쌓는다.**
5. 새 글을 확인한 대상은 **반영한 내용이 없어도** `lastScrapedPostDate` 를 확인한 가장 최근 글 날짜로 갱신한다(같은 글을 다음 날 다시 읽지 않게). 확인하지 못한 대상(로그인 화면 등)은 그대로 둔다. 이 날짜는 관리자 페이지의 "마지막 스크랩" 표시에만 쓰이고 붉은 점과는 관계없다.
6. 타임테이블이나 라인업에 새 아티스트가 있으면 `src/data/catalog/artists.ts` 에 다른 이름을 더한다(찾기에만 쓰임): 공식 한글·영문 표기(아티스트·소속사 채널, 국내 예매처), 같은 아티스트를 다른 페스티벌이 다르게 쓴 표기, 출처가 있는 약칭(위키 문서, 공식 채널·댓글에서 쓰이는 것). 확실하지 않은 이름, 비하 별명, 멤버 개인 별명은 넣지 않는다.
7. 새로 반영한 내용이 있으면, 그 회차의 `updatedAt`(`src/data/catalog/index.ts` 의 `CATALOG` 항목)을 **오늘 날짜**로 바꾼다. 이 날짜가 사용자가 마지막으로 본 날짜보다 새로우면 앱의 관리 탭과 그 페스티벌에 붉은 점이 뜬다(`src/data/updates.ts`). 타임테이블·라인업·주의사항·안내 이미지·예매처·지도·핀을 바꿨을 때, 닫아 둔 탭을 열었을 때 모두 해당한다. **확인 날짜(`lastScrapedPostDate`)만 바꾼 날에는 `updatedAt` 을 바꾸지 않는다**(새 내용이 없는데 붉은 점이 뜨면 안 된다).

## 새 회차가 처음 나왔을 때

공식 채널에 다음 회차의 **날짜**가 글로 올라오면(개최 확정·일정 발표·블라인드 티켓 안내 등) 그 회차를 만든다. 현장 화면·나무위키·기사에만 있는 날짜로는 만들지 않는다.

- 연도 파일을 새로 만든다(기존 연도 파일을 본뜸). id 는 새 UUID(`uuidgen | tr A-Z a-z`), 연도 코드 = 페스티벌 코드 + 연도.
- `src/data/catalog/ids.ts` 와 `CATALOG`(`src/data/catalog/index.ts`)에 등록한다.
- **타임테이블과 지도 탭은 닫아 두고 만든다**(사용자 요청 2026-11-07): `CATALOG` 항목에 `closedTabs: ['timetable', 'map']`. 앱에서 두 탭이 흐리게 눌리지 않고, 정보 탭이 먼저 열리며 맨 위에 "올해 공식 발표가 나오면 열려요"가 뜬다. 라인업·타임테이블이 나오면 타임테이블 탭을, 그해 지도가 확인되면 지도 탭을 연다(위 3번).
- 장소·지도·지도 핀은 페스티벌 코드 단위라 새로 만들지 않고 지난 회차 것을 그대로 쓴다(지도 탭을 열 때까지는 보이지 않는다). 장소가 바뀌었으면(예: 뷰민라 2026 올림픽공원 → 문화비축기지) 장소와 핀을 고친다.
- **같은 장소라도 배치가 바뀔 수 있으니** TODO "다가오는 회차 지도"에 그 회차 줄을 더한다: `- [ ] <이름> <연도> (<시작일>–<끝일>, <장소>): 공식 지도 미공개 — 지도 탭 닫힘`. 그해 공식 지도가 나오면 위 MAP 처리대로 비교한다.
- 공식 예매처(공홈·공식 글이 거는 예매 페이지)를 연도 파일의 `…_TICKETS` 로 넣고 `CATALOG` 항목의 `tickets` 에 잇는다. 아직 모르면 `[]`.

## 마무리

- 바뀐 것이 없으면 커밋하지 않는다.
- 공식 지도 원본만 저장했으면 `chore(collect): <회차> 공식 지도 원본 저장` 으로 커밋하고, HISTORY 에 어느 글(날짜·주소)에서 받았는지 한 줄 남긴다.
- 바뀐 것이 있으면 `npm test && npm run build` 를 통과시킨다. 그다음 한글로 커밋하고 push 하고, GitHub Actions 배포가 성공했는지 확인한다.
  - 새 내용을 반영했으면 `feat(catalog): …` 로 커밋하고, `docs/HISTORY.md` 에 무엇을 어느 글(날짜·주소)에서 가져왔는지 한두 줄 남긴다. 끝난 일은 `docs/TODO.md` 의 "## 완료" 날짜별 목록에 `(수집)` 으로 적는다.
  - 확인 날짜만 바뀌었으면 `chore(collect): 수집 확인 날짜 갱신 (대상들)` 으로 커밋한다. HISTORY·TODO 에는 남기지 않는다(커밋과 보고로 충분하다).
- 마지막에 짧게 보고한다: 새로 반영한 것 / 새 글이 없던 대상 / 확인하지 못한 대상(이유).
  - **지도 남은 것**: TODO "다가오는 회차 지도"에서 30일 안에 시작하는 회차를 한 줄씩 적는다. 예: "원더리벳 2026(11/20) — 공식 지도 미공개", "○○(12/1) — 원본 있음, 그리기 전". 오늘 공식 지도를 새로 찾았으면 보고 맨 앞에 "지도 그릴 것"으로 적는다.
  - 행사가 끝난 회차의 줄은 TODO "지난 회차 지도"로 옮긴다(다음 회차 때 다시 본다).

## 참고

- 브라우저 도구가 없는 환경이면, 공홈은 `curl` 로 목록 HTML 을 받아 거른다. 인스타는 브라우저가 있어야 볼 수 있으니 "확인 못함"으로 둔다.
- 공식 이미지는 출처(공식 인스타·홈페이지)를 `source` 에 적는다.
- 내려받은 파일은 임시 폴더에 두고, 저장소에는 변환한 결과물만 넣는다.
